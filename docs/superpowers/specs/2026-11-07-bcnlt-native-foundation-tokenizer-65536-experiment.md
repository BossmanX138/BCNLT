# BCNLT Native Foundation Tokenizer: 65,536-ID Experiment

## Decision

The primary native-foundation tokenizer candidate has exactly **65,536 primary
token IDs**. This is an experimental lineage, not a promotion of or mutation to
the frozen Runeforge/BCNLT-v1 tokenizer.

A 32,768-ID tokenizer is retained only as a matched control. The purpose of the
control is to measure whether the larger vocabulary earns its additional model
parameters; it does not prevent the 65,536-ID candidate from being the primary
candidate.

## Lineage boundary

- The preserved 32,000 Runeforge IDs and 73 appended BCNLT-v1 structural IDs
  remain unchanged in their existing artifacts.
- The native 65,536-ID tokenizer is induced from scratch and does not inherit
  the old numeric ID layout.
- The meanings represented by the 73 structural tokens remain required seed
  semantics, but the native artifact assigns its own deterministic IDs.
- Common Core remains immutable. Validated learned meanings enter the
  append-only Extended Core and never rewrite Common Core.
- Every artifact records corpus hashes, induction configuration, allocation,
  factor schemas, byte-fallback contract, and tokenizer digest.

## Model contract

- Input embeddings and the language-model output head are tied.
- The 65,536 primary IDs include normal text/code pieces, structural tokens,
  special/control tokens, byte fallback, and evidence-approved Extended Core
  entries.
- Compositional surface, semantic-role, training-role, and speech/phonetic
  factors are auxiliary channels. They do not consume separate ranges of the
  65,536 primary IDs.
- Raw acoustic codebooks, if added later, are outside the text/code primary
  vocabulary.
- The vocabulary embedding parameters count toward the model's advertised total
  parameter budget. For hidden width `d_model`, the tied table contains
  `65,536 * d_model` parameters.

## Required induction behavior

1. Respect Unicode extended-grapheme boundaries.
2. Preserve protected code boundaries for operators, delimiters, literals,
   comments, identifier morphology, and validated syntax units.
3. Guarantee exact lossless encoding through explicit byte fallback.
4. Allocate ordinary pieces from admitted English and multilingual code data,
   rather than padding the vocabulary with unsupported rare strings.
5. Allocate learned semantic identities only from validated Extended Core
   evidence.
6. Reject secrets, high-risk memorization candidates, provenance failures, and
   insufficiently supported pieces.

## Matched experiment

The 65,536 candidate and 32,768 control must use the same:

- admitted corpus and split hashes;
- structural/factor schemas;
- model architecture other than vocabulary-dependent rows;
- total training-token or compute budget;
- initialization policy and seed set;
- evaluation suites and stopping rules.

Report both a fixed-transformer comparison and a fixed-total-parameter
comparison. In the fixed-transformer comparison the larger vocabulary increases
the total model size. In the fixed-total-parameter comparison the transformer
body is adjusted so both complete models have the same total parameter count.

## Promotion gates

The 65,536 candidate can be promoted only if it passes:

- exact text, code, malformed-input, and arbitrary-byte round trips;
- English plus every admitted programming-language coverage floor;
- structural and semantic boundary preservation;
- executable-code and downstream matched-model evaluation;
- generated bytes per second, latency, peak-memory, and sequence-length reports;
- rare-token utilization and minimum-training-support checks;
- tokenizer membership-leakage and secret-exposure audits;
- reloadable artifact and deterministic-manifest validation.

Compression, bits per byte, token-level perplexity, or training loss alone cannot
promote the tokenizer.

## Current authorization boundary

This decision authorizes building and evaluating the isolated 65,536-ID
candidate. It does not authorize modifying preserved tokenizer/model artifacts,
starting a full 0.5B pretraining run before corpus admission and tokenizer gates
pass, merging weights, or publishing an artifact.
