# Task runtime reuse gate (2026-11-23)

## Boundary

The task reuse gate accelerates a parser-runtime transition without pretending an old
task database was generated by the new runtime. It creates a new current-lineage task
database and copies only rows backed by three independent proofs:

1. the exact historical task database bytes have a passed v2 full-audit manifest;
2. a fresh admission comparison matches the immutable per-document runtime-delta receipt;
3. the document remains admitted and eligible under the candidate runtime.

The migration receipt always records `training_ready: false`. Normal packing and the
full current-runtime task audit are still mandatory afterward.

## Copied and regenerated state

For a reusable document, the SQL transaction copies the document ledger, task-token
blobs, loss boundaries, example IDs, and task rejections. It changes only:

- `semantic_spec_sha256` to the candidate document's specification hash;
- `parser_runtime_identity_sha256` to the candidate runtime identity.

Example IDs do not include those provenance fields. The end-to-end regression verifies
that reuse followed by ordinary packing produces the same logical database identity as
a completely fresh current-runtime pack.

Documents are left for ordinary repacking when they are changed, candidate-only,
ineligible, absent from the audited baseline task ledger, or otherwise unproved.

## Command

```powershell
python scripts/migrate_reusable_runtime_tasks.py `
  --baseline-task-database <audited-old-tasks.sqlite> `
  --baseline-task-audit-manifest <old-task-audit-v2.json> `
  --baseline-admission-database <completed-old-admission.sqlite> `
  --candidate-admission-database <completed-current-admission.sqlite> `
  --admission-delta-receipt <runtime-delta.json> `
  --source-catalog <frozen-catalog.sqlite> `
  --candidate-eligibility-root <current-eligibility-directory> `
  --candidate-eligibility-manifest-sha256 <sha256> `
  --forced-split <validation-or-test-for-frozen-evaluation-only> `
  --target-database <new-current-tasks.sqlite> `
  --output-receipt <new-reuse-receipt.json>
```

Omit `--forced-split` for the training inventory. Frozen validation and test
inventories must supply their exact task split; `reserved_heldout` inventories use
`test`. The migration rejects a forced split that does not match the eligibility
manifest's source split policy.

Both output paths must be new. The target remains `packing_complete=false` until the
normal packer processes all non-reused documents and performs its normal completion
transition. A fresh v2 full-task audit must then bind the finished database bytes.
